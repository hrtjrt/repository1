# 2026-08-30 工作日志

## 修复「缺后端」导致的前端报错（json-server 方案）
项目：usercenter_frontend_vue（Vue3 + TS + Pinia + ant-design-vue）。原设计用 json-server + db.json 作 mock 后端，vue.config.js 的 devServer.proxy 把 /api 转发到 http://localhost:8080。后端未启动时所有 /api 请求 ECONNREFUSED，且调用方均无 try/catch，导致控制台报错/页面卡死。

### 已完成的改动
1. 安装 `json-server@0.17.4`（devDependency）。
2. 新增 `mock/middleware.js`：按 /register /login /logout /current /search /delete 原样返回 db.json 的 RPC 信封（{code,data,message}），绕开 json-server 的 REST 语义，使前端 `res.data.code === 0` 判断全部成立。注意 proxy 已剥掉 /api，json-server 收到的是 /login 等（不带 /api）。
3. package.json 增加脚本：`mock`（启动一次）、`mock:watch`（监听 db.json）。
4. 修复 `src/access.ts` 权限判断：`loginUser.userRole !== 1` 与 db.json 的字符串 "admin" 类型不匹配，且默认 loginUser 无 userRole。改为 ADMIN_ROLES = ["admin","1",1] 并兜底缺字段。
5. 丰富 `db.json` 的 search 数据，补齐 userAccount/gender/createTime/avatarUrl，userRole 用数字 1/0（匹配 adminUserManagePage 模板里的 `record.userRole === 1`）。
6. 给 store.fetchLoginUser、adminUserManagePage 的 fetchData/doDelete、userLoginPage/userRegisterPage 的 handleSubmit 全部加 try/catch，避免 mock 未启动时崩溃；注册失败提示加可选链 `res.data?.description ?? ''`。

### 验证
- json-server 启动后 curl /current /search /login /register /logout /delete 均返回正确信封（/delete 需合法 JSON 体，前端发送的是合法 JSON）。
- `npm run build` 通过（EXIT=0），仅预置的 unused-vars 警告，无错误。

### 运行方式
- 后端：`npm run mock`（端口 8080）
- 前端：`npm run serve`（端口 3000，proxy 转发 /api → 8080）
- 注意：json-server 进程需保持运行；缺依赖声明（@ant-design/icons-vue、dayjs 靠 ant-design-vue 提升安装，建议补到 dependencies）。
